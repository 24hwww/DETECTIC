6. HOW nrd RECEIVES WI-FI DATA
-------------------------------
The binary uses a hybrid event path:

A. libos UNIX-domain socket IPC (event / control messages)
   - msg_init()   @0x402510  creates an AF_UNIX SOCK_DGRAM socket
   - msg_srvInit()@0x4024e0  binds it to /var/tmp/<msg_type>
     (pattern observed in libos.so: /var/tmp/ + msg_type decimal)
   - msg_recv()   @0x402200  uses recvfrom() on this socket
   - The nrd server is registered in the main poll loop
     (nrd init @0x405ee4 -> msg_srvInit(0x2d, ...) then
      0x409aa4 adds the socket to the poll list with callback 0x405b98).
   - The receive/dispatch function at 0x405b98 reads 0x1008-byte
     messages, uses the first 4 bytes as a message type and looks up
     the handler in a small table at 0x478488.

B. Netlink (rtnetlink) for driver events
   - mtk_wlanifBSteerEventsCreate @0x449d70 opens an AF_NETLINK socket
     (SOCK_RAW, protocol seen as 0 for NETLINK_ROUTE and 0x15/21 for a
     vendor/QCA-style netlink family) and binds it with nl_groups=1.
   - The netlink fd is also registered with the poll loop
     (0x44c2a0 calls 0x409aa4) so that incoming wireless events
     (IWEV_*, new link, scan, probe) are processed in the main loop.

C. Direct ioctl() / WEXT and iwpriv popen()
   - Many functions open AF_INET/AF_UNIX raw sockets and call ioctl()
     with WEXT/SIOCGIWFIRST style commands to query stations, VAP MAC,
     channels, etc.
   - String at 0x5ded0: "iwpriv %s set DisConnectSta=..." indicates
     nrd runs iwpriv via popen()/pclose() to force a STA disconnect
     during steering.

D. Data files
   - cJSON_GetRootFromFile, cJSON_Parse and file open/fscanf indicate
     nrd loads its configuration from JSON.
   - It reads /tmp/easyMesh_agent_AL_MAC for the AL MAC address and
     station info files (sscanf paths observed in the strings list).

8. PROBE / RSSI HANDLER DISASSEMBLY
-----------------------------------
A. Probe request (non-associated STA) - wlanifBSteerEventsHandleProbeReqInd
   Range: 0x0044a0d4 - 0x0044a25c

   The function receives an event pointer (x0 = device state, x1 = probe
   event, x2 = BSS info).  It extracts:
     - STA MAC: 6 bytes at offset 0x8 inside x1
     - RSSI:    byte at offset 0xe inside x1
     - channel: halfword at offset 0x2 inside x2
     - band:    byte at offset 0x4 inside x2

   It then logs:
     "%s: Probe request from %02X:%02X:%02X:%02X:%02X:%02X: RSSI %2u
       APId %-3d ChanId %-3d ESSId %-3d"   (@0x45e4a0)

   After logging it calls:
     stadbFindOrInsertEntry(1, 0, 0, <MAC buffer on stack>, 0x20) @0x404a48

   This inserts or locates a station database entry keyed by the MAC
   address, then returns.  The second log line prints probeEvent.rssi
   before the stadb call (format @0x45e500).

B. RSSI measurement - wlanifBSteerEventsHandleRSSIMeasurementInd
   Range: 0x0044a99c - ...
   Extracts the same MAC/RSSI/channel/band fields and passes them to
   netdbHandleRSSIMeasurementEvent / stadbHandleRSSIMeasurement,
   which update the station and network databases.

C. RSSI crossing - wlanifBSteerEventsHandleRSSIXingInd
   Range: 0x0044a784
   Triggers steering decisions when an RSSI threshold is crossed.

D. Network database state machine
   - netdb_setCandidateProbeStateForSTA @0x415bb8 sets
     "probe witholding" / probe-candidate state for a STA on a VAP.
   - netdb_setChannelStateForSTA @0x415dc8 sets per-channel state.
   - netdb_setCandidateStateForSTA @0x4159c8 sets generic candidate state.

9. INTERNAL DATA STRUCTURES / DATABASES
----------------------------------------
nrd maintains at least two in-memory databases:

A. stadb (Station Database)
   - Table base referenced at 0x47c000+0x7b8.
   - Entries keyed by STA MAC.
   - Evidenced operations:
       stadbFindOrInsertEntry    @0x417a48
       stadbHandleRSSIMeasurement@0x418d88
       stadbEntryUpdateTimestamp @0x51e58
       stadbEntry_setUplinkRSSI  @0x51f60
       stadbEntry_setRCPI        @0x51f98
       stadbEntryBSSStatsUpdateTimestamp @0x52108
   - Stores per-STA fields: MAC key, activity timestamps, uplink RSSI,
     RCPI, BTM/RRM capability flags, black/white lists, steering state.

B. netdb (Network/BSS Database)
   - Tracks local and remote BSSs by APId / ChanId / ESSId / BSSID.
   - Evidenced operations:
       netdb_apHandleCreate           @0x411ad4
       netdb_apHandleResolveWlanIfaces@0x410ef0
       netdb_getBSSesSameESS          @0x50780
       netdb_getScanBSSes             @0x507b0
       netdb_setCandidateProbeStateForSTA @0x415bb8
       netdb_setChannelStateForSTA    @0x415dc8
       netdbHandleRSSIMeasurementEvent@0x413df8
   - Stores: BSSID (6 bytes), channel, band, PHY mode, ESS ID,
     VAP interface name, scan results, candidate/probe-withholding state.

C. Steering / threshold configuration
   - Many threshold strings (InactRSSIXingThreshold, LowRSSIAPSteering,
     Delay24GProbeRSSIThreshold, etc.) show the configuration is kept in
     JSON / .data and applied against the station and network databases.

10. EXTERNAL EXPOSURE / INTER-PROCESS COMMUNICATION
----------------------------------------------------
A. Sockets / IPC
   - nrd does NOT call listen() or accept() in its PLT.
   - It does call socket(), bind(), sendto(), recvfrom() and poll().
   - bind() is used for:
       * libos Unix domain datagram sockets under /var/tmp/<msg_type>
       * Netlink sockets (rtnetlink / vendor netlink family)
       * AF_INET sockets used only for ioctl() queries
   - Communication with other daemons is therefore via local Unix
     domain sockets (libos message queue abstraction) and netlink, not
     a network API.

B. Shared memory
   - shmat / shmdt / shmget are NOT in the import table.
   - No shared-memory segments are created.

C. Message queues
   - libos functions are named msg_*, but they are implemented on top
     of AF_UNIX SOCK_DGRAM sockets, not System V message queues.

D. Logs / CLI
   - openlog / syslog / printf are used; logs are exposed to syslog.
   - No dedicated CLI socket or telnet server inside nrd.
   - The JSON config is read from files (cJSON_GetRootFromFile).
   - nrd writes /tmp/easyMesh_agent_AL_MAC and can run iwpriv/system
     commands.

E. Accessibility classification
   - In-memory stadb/netdb data is not directly exposed to remote
     hosts or other unprivileged users.  It is available to:
       * local privileged processes that connect to nrd's Unix socket
       * other daemons that nrd itself messages (hostapd/apsd/wpsd via
         msg_connCliAndSend / sendto)
       * any process that can read syslog or attach with ptrace.

11. NON-ASSOCIATED STA / PROBE-REQUEST CAPABILITY
--------------------------------------------------
YES - nrd can obtain and act on non-associated STA information.

Evidence:
  - Function wlanifBSteerEventsHandleProbeReqInd @0x44a0d4 explicitly
    receives a probe-request indication and extracts:
      * STA MAC (6 bytes at event+0x8)
      * RSSI    (byte at event+0xe)
      * APId / ChanId / ESSId from the BSS info
      * channel/band
  - It logs this data at format string 0x45e4a0:
      "Probe request from %02X:...: %02X: RSSI %2u APId ... ChanId ... ESSId ..."
  - It calls stadbFindOrInsertEntry @0x404a48 to store the MAC in the
    station database.
  - netdb_setCandidateProbeStateForSTA @0x415bb8 is used to mark the
    probe-candidate / probe-withholding state for that STA on a VAP.
  - The data is used by the steering algorithm (steeralg_*) to decide
    whether and where to steer the client before it associates.

Data placement summary:
  MAC       -> stadb entry key, also logged/copied to stack buffer
  RSSI      -> logged as probeEvent.rssi, later used by
               stadbHandleRSSIMeasurement / stadbEntry_setUplinkRSSI
  Channel   -> BSSInfo -> netdb BSS record (ChanId)
  BSSID     -> netdb BSS record (bssid field)
  Timestamp -> stadbEntryUpdateTimestamp / stadbEntryBSSStatsUpdateTimestamp

13. SUMMARY CLASSIFICATION
--------------------------
- nrd is a Qualcomm/Atheros/TP-Link EasyMesh / band-steering daemon.
- It receives Wi-Fi events through a mixture of libos Unix-domain
  sockets, netlink sockets and direct ioctl()/WEXT/iwpriv calls.
- It maintains in-memory station (stadb) and network/BSS (netdb)
  databases; these are not externally queryable over the network.
- It CAN observe and store non-associated STA probe requests,
  including MAC, RSSI, channel and timestamp, in stadb/netdb.
- Data is exposed only to other local privileged processes via
  Unix sockets / netlink and via syslog; there is no shmat/shmdt
  and no TCP/UDP listen server.
