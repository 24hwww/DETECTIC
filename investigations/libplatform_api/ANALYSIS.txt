3. HOW THE HAL TALKS TO THE MEDIATEK DRIVER
--------------------------------------------------------------------------------

Primary path: an INET DGRAM socket is opened once and stored in g_ioctl_sock
(or a local int).  The HAL then calls:

    ioctl(fd, 0x8be1, &struct iwreq)

0x8be1 is in the Linux wireless private-ioctl range (SIOCIWFIRSTPRIV+1).
The iwreq is laid out as:

    .ifr_name      = interface name (ra0, rai0, rax0, ...)
    .u.data.pointer -> caller-allocated data buffer
    .u.data.length  = buffer length
    .u.data.flags   = 16-bit OID/sub-command

Known OID/sub-commands placed in iwreq.u.data.flags:
  0x0a01 (2561)  - associated station list
  0x0a03 (2563)  - used by unassoc link metrics / timestamp path
  0x0a05 (2565)  - used by getRadioMetrics
  0x0b04 (2820)  - scan results (getScanResult)
  0x0b05 (2821)  - RSSI (getRssi second ioctl)
  0x0b07 (2823)  - radio info (getRadioInfo, not in target set)
  0x0b11 (2833)  - WPS status

Other ioctl() request values seen:
  0x8913 (35091) - SIOCGIFMEM / get interface memory/status flags
  0x8927 (35111) - SIOCGIFHWADDR
  0x89f0 (35312) - SIOCDEVPRIVATE (used by Ethernet/switch functions)

For action/configuration the HAL shells out:

    system("iwpriv <ifname> set <cmd>=<val>")

For driver events it uses:

    socket(AF_NETLINK, SOCK_RAW, 0)
    bind() with sockaddr_nl { family=AF_NETLINK, nl_pid=getpid(),
                             nl_groups=1 }
    recvmsg() / netlink RTM_NEWLINK parsing

File reads (read-only):

  /sys/class/net/%s/carrier

8. PEER / EASYMESH REQUIREMENT CONCLUSION
--------------------------------------------------------------------------------

All functions in the analysed set are local MediaTek HAL helpers. They open
sockets, issue ioctls/iwpriv commands, or read files. There is no socket
communication with a remote 1905 controller/agent, no 1905 packet encoding, and
no dependency on an EasyMesh peer. They can be called locally by any process
that links libcutil.so and has privileges to open the wireless interface.

--------------------------------------------------------------------------------
9. SECURITY / PRIVACY NOTES FOR DETECTIC
--------------------------------------------------------------------------------

- The HAL operates on raw MAC addresses.  getScanResult, getBSSID,
  getAssociateStaList, getUnassocStaLinkMetrics all expose 6-byte BSSIDs/MACs.
- No /tmp files are written by these get functions, but getWpsInfo reads
  /tmp/wps_en_<ifname> and /tmp/wps_st_<ifname> if they exist.
- doScan and setUnassocLinkMetrics execute system("iwpriv ...") and therefore
  require command-injection awareness if any argument is user-controlled.
- The 0x8be1 private ioctls need a socket with appropriate privileges; on a
  stock OpenWrt/EX520 system these are normally usable by root or the wireless
  daemon.
